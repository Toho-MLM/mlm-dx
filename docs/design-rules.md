# MLM-DX デザインルール

承認済み・2026-09-27。UI・操作・通知を変更するエージェント向けの一次情報。

## 適用

- 新規画面と変更対象に適用する。既存実装の不一致をコピーせず、変更範囲で解消する。全画面改修・ブランド変更・ダークモード対応を自動で追加しない。
- 優先順：業務・権限・日時の仕様 → 本ルール → 共通部品 → 画面固有の調整。UI都合で業務制約を追加しない。
- 「必須」は守る。「原則」は理由のある例外を認める。「目安」は内容量で調整する。例外は対象・理由・代替手段・確認方法を記録する。**toast統一・inlineメッセージ禁止は例外にしない。**
- 実装は `$web-feature`、検証は `$verify`、コミット依頼時は `$commit` を使う。基準の承認と実装への適用完了を混同しない。

## 通知

- エラー・入力検証・成功・警告・案内は、既存の Sonner とルートの `Toaster` に統一する。**inlineメッセージは禁止**。入力欄下、フォーム内、一覧内、画面上部の Alert・バナー・補足文へ通知を出さない。
- 項目ラベル・件数・受付状態などの業務データは通常表示する。操作不可の理由・状態変化・空状態を通知する文は toast に出す。
- 日本語で対象・結果・次の操作を伝える。APIエラーは既存の対応表で変換し、未登録コードには利用者向けの代替文を用意する。
- 1操作につき1回。同じ事象はIDを共有して更新し、再描画・入力中・再接続で連発しない。複数の入力エラーは1つにまとめ、最初の不正な入力へフォーカスを移す。`aria-invalid`・枠の強調は併用可。
- 成功・案内は約5秒で閉じ、hover・フォーカス中は停止。エラー・要確認は手動で閉じるまで保持する。成功・案内は polite、エラーは assertive で読み上げ、通知だけでフォーカスを奪わない。
- 再試行・結果確認は toast のアクションで提供する。閉じた後も画面の操作から復帰できるようにする。

## 入力・非同期処理

- ラベルを常時表示し、placeholderだけで項目名を伝えない。初回検証は送信時、不正になった欄は修正中にも再評価する。
- 初回取得中は `Skeleton`。取得中を0件扱いしない。取得失敗時は既存データを保持し、最新でない旨と再読み込みを toast で通知する。
- 送信中は二重実行を防ぎ、操作名・ボタン幅を保つ。入力と確定操作を無効化する。
- 成功はAPIで確認してから通知・閉じる・一覧反映を行う。更新失敗時は入力を保持する。
- 通信切断・タイムアウトは保存失敗と断定しない。結果不明を通知し、最新状態を確認してから再送の可否を決める。
- 競合・受付終了は入力を保持して最新状態の確認へ誘導する。古い値での上書きや同じ更新の自動再送は禁止。
- 権限のない管理操作は原則非表示。一時的な制約は無効表示＋理由を通知する操作を用意する。無効ボタン自体で通知する場合は `aria-disabled` と実処理の抑止を併用する。
- 変更不能な値は読み取り専用。管理者モードの入口は既存サイドバーへ集約する。権限喪失時は入力を保ち、再ログイン・一覧への復帰を toast で案内する。

## 操作・ダイアログ

- 同じ操作領域の主要ボタンは原則1つ。主要操作は `default`、戻る・キャンセルは `outline`、削除は `destructive`。ラベルは結果が分かる動詞にする。
- **確定操作はスマホでも常に右寄せ、全幅禁止。** `DialogFooter` を使い、キャンセル・戻る → 確定の順、間隔8px。収まらなければ右寄せのまま折り返す。
- 開く際は対象の最新値で初期化し、見出しか最初の入力へフォーカスを移す。Tabは内部を巡回する。
- 未変更なら Esc・閉じる・キャンセルで閉じる。未保存の変更を失う場合は「編集を続ける／破棄」で確認する。
- 中断不能な送信中は閉じる・Esc・外側クリックも抑止する。タイムアウト後は結果確認へ進める。
- 閉じた後は起点へフォーカスを戻す。起点が消えた場合は一覧見出しなどへ戻す。
- 削除確認は対象名・件数と実際の影響を示す。復元不能な操作だけ「取り消せません」と書く。
- 高さ不足は本文をスクロールさせ、上下16px以上の余白と見出し・確定操作への到達性を確保する。

## 見た目・構成

- `apps/web/components/ui`、共通ヘッダー、Lucide、既存Tailwindトークンを再利用する。色・間隔・ブレークポイントを画面ごとに増やさない。
- 共通部品は見た目・基本操作を持ち、利用側はデータ・権限・検証条件・送信・成功後の反映を持つ。
- 見出しで分かる内容の説明を重ねない。判断に必要な締切・条件・影響のみ補足する。

| 対象 | 基準・目安 |
| --- | --- |
| 文字 | 既存の Noto Sans JP。見出し18–24px、本文14–16px、補足12px、スマホ入力16px |
| 色 | 主要操作は既存 `primary`。成功は緑、要確認は黄褐色、失敗・削除は赤、終了・無効はグレー。必ず文字を併用。分類色には別の凡例 |
| コントラスト | 通常文字4.5:1以上、操作を識別する線・アイコン3:1以上。実際の背景・hover・選択状態で確認 |
| 間隔・角丸 | 間隔4/8/12/16/24/32px。ラベル間8px、項目間16px、まとまり間24–32px。角丸4/6/8px、ボタン6px・カード8px |
| 幅・余白 | 本文 `p-3 sm:p-4`、カード内16–24px、単独フォーム最大640px。Dialogは幅512px・内側24px・スマホ左右16pxが基本 |
| ヘッダー | 高さ56px、文字16–18px。ページ名と主要操作。検索・絞り込み・並び順は本文。狭い幅では補助操作をメニューへ |
| 操作領域 | 既存Button/Inputは高さ36pxを起点に、スマホの操作領域は44px目安。アイコン描画16px。名前とフォーカス表示を付ける |
| 動き | 状態変化150–200ms。装飾的な拡大・強い影を抑え、動きを減らす端末設定に対応 |

- 比較は表、対象選択はリスト・カード、時間の重なりはカレンダー。比較表・カレンダーは利用可能な幅と領域内スクロールを使い、フォームは狭い画面で1列にする。
- 締切・料金・選択状態・実行結果・確定操作は隠さない。長い名称は原則折り返す。省略時はタップ・フォーカスでも全文確認を可能にし、hoverだけに依存しない。
- データ0件と絞り込み結果0件を区別し、後者には条件クリアを用意する。一括操作は選択範囲・件数を明示し、部分失敗時は成功件数・失敗対象を toast で通知して失敗分を見直せるようにする。

## 日時・予約・同期

- JST・24時間表記。日付と時刻の境界は既存仕様に従う。同日予約は日付＋開始時刻＋終了時刻、日またぎは開始日時＋終了日時。日またぎは終了日、年またぎは両年も表示する。
- 締切は相対時間だけでなく絶対日時・JSTを示す。APIの可否と一致させ、端末のタイムゾーンに依存させない。
- 抽選は受付期限・抽選実行日時・利用日時・希望順位・申込名義を区別する。受付済みを予約確定と表示しない。結果・取消後の操作はAPIと業務条件に合わせる。
- ドラッグ選択はフォームで確認してから保存する。日時の直接入力や、ドラッグ以外の移動操作も用意する。
- 接続状態と保存状態を区別する。切断・再接続・競合はスマホでも toast で通知し、最新状態を確認する。

## 検証・完了

変更範囲に関係する条件を選び、`操作／期待結果／実際の結果` を確認する。

- 連打：送信1回、操作名・幅を維持。必須項目空欄：toast＋対象へフォーカス、ほかの入力を保持、inlineメッセージなし。
- 取得・更新失敗、通信切断、競合：適切な通知と復帰。toastを閉じても再確認可能、重複送信・古い値の上書きなし。
- 未保存で閉じる、Tab・Shift+Tab・Esc：破棄確認、順序、フォーカス復帰。toastの重複・読み上げ・自動終了条件も確認。
- レイアウト：360/390/768/1280px、名称40字、文字200%、ソフトウェアキーボードで主要情報・確定操作に到達可能。横移動は表・カレンダー内。
- 権限・日時に影響する場合：一般／管理者、締切直前・一致・直後、JST 0時、異なる端末タイムゾーン。
- 共通部品の変更は代表的な利用画面も確認。アプリ別の type-check 等は `$verify` に従う。未実施は理由を報告し、合格扱いにしない。
- 変更による違反は修正する。適用した基準・確認結果・未実施・範囲外の既存差分を簡潔に報告。検証後に変わっていない差分は再検証不要。
- 共通部品への適用順：通知・非同期処理 → フォント・色 → 操作領域・動き。ルール変更は本書を更新し、工程が変わる場合だけ AGENTS.md・該当スキル・README も揃える。
